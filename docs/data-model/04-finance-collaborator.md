# MASTER DATA MODEL — 04 · Finance & Collaborator (money)

## 1. Scope

This slice covers **every table that holds, promises, moves, un-does or proves money**. Its authority is
[`../design/finance-commission-spine.md`](../design/finance-commission-spine.md) (the financial spine —
**15 tables**, INV-1 … INV-26, [D-FS-1] … [D-FS-12]), which beats every phase contract on anything touching
money; then [`../design/resolutions.md`](../design/resolutions.md) (§2 ownership maps, §4 decision registry
D16-D60, §8 do-not-change). The phase contracts read for implementation detail are
[`../phases/phase-08-09.md`](../phases/phase-08-09.md) (the `collaborators` parent record, commission-rule
screens, referral capture and the click-evidence table), [`../phases/phase-10-12.md`](../phases/phase-10-12.md)
(the 21-file atomic migration set, the model plan, the two commission engines, wallet, ledger, payouts,
statements, reconciliation) and [`../phases/phase-13.md`](../phases/phase-13.md) (invoices, invoice items,
expenses, other income, payment methods, finance categories, `finance_reversals`). Conventions are
`CLAUDE.md` §1-§3 and `docs/phases/phase-01.md` (`Ability` presets, `PermissionRegistry`, `Money`, module
gating). **26 tables are defined here**: 15 spine + 7 Phase 13 + 4 Phase 8/9 (the parent and the referral
evidence the money tables hang off). Nothing below is asserted unless a contract defines it; where two
contracts still disagree after convergence the clash is recorded in §7 and **no name is invented**.

**Legend used in every table.** **M** = money `decimal(15,2)`, written only through `App\Support\Money`
(bcmath, intermediate scale 6, final half-up at 2 — INV-7). **%** = percentage `decimal(8,4)` (F-7.1,
`CLAUDE.md` §3). **G** = generated STORED column (raw SQL; the migration must fail loudly — spine R-3).
**AO** = append-only: no `deleted_at`, a model `deleting` hook **and** a `BEFORE DELETE` trigger raising
`SIGNAL SQLSTATE '45000'` (INV-5, D16, D17). **SD** = carries `deleted_at`. **enc** = Laravel `encrypted`
cast, never logged, never rendered, `[encrypted]` in an activity diff.

## 6. FINANCIAL INTEGRITY MAP

Read this section alone and you can audit the design. Every hop names the **table**, the **guard the
database itself enforces**, the **transaction boundary**, and the **spine invariant** that protects it.
Two rules hold at every hop: **the INSERT is the check** (no code path decides "does this exist?" with a
SELECT — under REPEATABLE READ two workers both read "no"), and the fixed lock order
**payment → document → entitlement → wallet → ledger rows ascending by id** (INV-20), with every event and
notification dispatched only through `DB::afterCommit()`.

### 6.3 The four duplicate-prevention layers, in one view (resolutions §8 item 4 — do not change)
